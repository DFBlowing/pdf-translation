## 案例 1 — Disco 智能全表面（公式密集的双栏期刊论文）

| | |
|---|---|
| 原文 | 14 页 · 9,652 英文词 · 72 个编号公式 · 6 图 · 2 表 · 46 条参考文献 |
| 译文 | 18 页 · 9,329 汉字 · 259 个可跳转链接 |

IEEE 双栏版式。这个案例的重点是**公式**：

- 73 个公式全部用 **KaTeX 重新排版** —— 真正的矢量字体（`KaTeX_Math-Italic` 等字体子集），不是裁图，也不是 Unicode 字符拼凑。因此可以缩放、可以对齐、打印质量正常。
- 公式**越栏判据**在这里踩过两个坑：一开始的过滤器会漏掉刚好擦过栏边界的那类溢出，修好判据后同一份文档从"0 处溢出"变成"16 处溢出"。
- 参考文献 `[n]` 是**跨版式稳定的锚点**，正文引用与文献表之间双向可跳转，且锚点闭环无悬空。

## 案例 2 — Stanford CS231n 讲义（纯文字 + 大量代码）

| | |
|---|---|
| 原文 | 191 页 · 50,529 英文词 · 82 图 · 0 个编号公式 |
| 译文 | 155 页 · 73,288 汉字 · 133 条外链 + 17 条目录/脚注跳转 |
| 实测耗时 | 约 **29 分钟**（13 个并行子 agent） |
| 实测产出 | **222,496** output tokens |

单栏讲义。这个案例的重点是**规模**、**代码块**与**链接**：

- 191 页拆成 **13 个并行批次**翻译。这是把墙钟时间从"几小时"压到"半小时"的关键 —— 成本的主导项是**轮次 × 上下文大小**，而不是译文长度。
- **代码原样保留**，只译散文。译文读者可以直接复制代码运行。
- 82 张图按原始位置归位；其中 **51 张带编号题注**（图 1–51 连续无缺口），原图本来就没有题注的 20 张保持无题注 —— 不补编号，也不编一段题注出来。
- 原文的 **251 条**链接标注逐条对齐：66 条站点 chrome 丢弃、52 条本就在、66 条接回、**67 条定位不到并如实报告**（可见文字已整体译成中文、不留拉丁痕迹）。成品 133 条外链。详见仓库 README 的「链接与导航也算内容」。

### ⚠️ 源文件本身的缺陷（重要）

这份 PDF 是从 HTML 转出来的，代码框用了 `overflow: hidden`，检测器在源文件里报出 **73 行**代码贴着裁切边界（分布 42 页）：

```
hidden_layer = np.maximum(0, np.dot(X, W) + b) # note, ReLU activ
                                                              ↑ 这就是框的边缘
```

**缺失的字符在 PDF 里根本不存在** —— 任何提取工具都取不回来，不是解析失败。

译文**从官方讲义逐处复原**，不猜测、不补全，也不留免责标注：

- 实测 72 处候选里，**65 处可机械证明已复原** —— 判据是输出在该处写下了**源文件里没有的字符**（`# get the gradi` → `# get the gradient`）。单纯的子串比对做不到这一点：被截断的片段本身就是复原结果的**前缀**，`in` 会把成功报成失败。
- 其余候选是检测器的边界误报（一行恰好停在完整单词上），逐条人工看过，确认也全部已复原 —— `x[ix] = old_value # restore to previous value (very important` 这行看着「完整」，其实括号到裁切处都没闭合。
- **成品里没有一处「原文截断」标注。** 逐条标注不是披露，是没修好。
